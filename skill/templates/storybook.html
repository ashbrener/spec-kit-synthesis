01 — The picture in one read

What the storybook is

A storybook is one faithful, whole-system architecture narrative reconciled from many sources. It is organised by architecture, never by authoring history — and every claim it makes is traceable to where it came from.

This page is not that narrative; it is the design system that renders it. Each section below exercises one family of components so the visual language can be judged in isolation. The reading model is progressive: the prose stands on its own, and detail is revealed in place rather than behind a mode switch.

The structural fact The renderer is a pure function of the model: same model in, byte-identical HTML out. That makes every run diffable and the faithfulness gate auditable. See §06.

"Organised by architecture, not by spec history — and never a claim without a source."

02 — The voice

Type & rhythm

Display in Fraunces, body in Newsreader, labels and code in Spline Sans Mono. A warm paper ground, generous leading, a single accent for emphasis.

A subheading, set in Fraunces

Body copy is a reading serif at a comfortable measure. Inline emphasis uses weight and the accent term treatment sparingly. Citations appear as quiet inline anchors such as a reference that resolve to the appendix.

A mono eyebrow label

  • Arrow-led lists carry parallel facts without numbering.
  • The accent glyph keeps the eye on the left margin.
  • Each item is one self-contained claim.
  1. Numbered steps imply sequence and dependency.
  2. Leading-zero counters keep the rhythm monospaced.
  3. Dotted rules separate without shouting.
03 — Marked passages

Callouts & citations

Three callout variants carry the three things a faithful atlas must mark out: a settled decision, an unspecified gap, and an evolution in the record.

DecisionA resolved architectural choice. Green left-rule. Maps to CalloutKind.decision; the body cites the source that settled it.
UnspecifiedA genuine gap — something the sources do not pin down. Red left-rule. Maps to CalloutKind.unspecified; the gate requires the body be non-empty.
EvolutionA superseded position kept for the record. Neutral rule. Maps to CalloutKind.evolution; cites the history entry, not the demoted claim.

05 — Depth in place

Disclosure

Detail opens where it lives, not behind a global mode. Tap a row to expand; deep-links open the targeted row automatically. Press e to expand all, c to collapse.

1The map phase — extractRead+

Each source fragment is read into typed claims, every one carrying at least one source reference. Fan out one reader per feature folder at scale.

It reads, then types, then grounds
  • Heading-split fragments become candidate claims.
  • Every claim carries a typed source reference.
  • A claim with no source cannot be constructed.
2The reduce phase — reconcileReason+

The product of the whole pipeline: overlapping claims merge, contradictions resolve to a current position, and superseded ones drop to history.

Where the value isReconcile is the editorial act — choosing the architecture spine. It stays grounded by pulling sources from the claims it keeps.
3The gate — verifyFail-closed+

Six checks run before anything renders. Exit zero only if provenance resolves, blocks are grounded, callouts have bodies, and the coverage note is present.
